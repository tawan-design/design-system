The big picture

What we were building, and who plays which role.

The goal of the session was not to design anything yet. It was to build the pipeline every future design-system change will travel through:

Change on a branch→Pull request→CI checks the code→Chromatic shows the visuals→You approve→Merge into main

By the end, we had sent one real change through that whole pipeline (PR #1), so we know it works.

Claude did

Visual review

Connect Chromatic, then send the first real change through the whole flow.

11

Connect Chromatic

You
Intent
Chromatic is your design-review tool. On every PR, it publishes Storybook online and shows before/after images of each component. You approve visuals without reading code.
You did
  1. Signed in to chromatic.com with GitHub (tawanuiux-202) and added the repo.
  2. Chose Storybook as the project type, because this repo already has Storybook.
  3. On the "Publish" screen, ran neither command. You only copied the project token (chpt_…).
  4. Saved the token as a GitHub secret in your terminal (command below).
Why you saved the secret
Claude Code isn't allowed to write secrets without your explicit permission. This is a safety rule, and it's a good one.
What a secret is
A value GitHub stores encrypted and only gives to the CI robot. It never appears in the code, even in a public repo.
gh secret set CHROMATIC_PROJECT_TOKEN -R tawan-design/design-system
# paste the chpt_… token when asked

Treat the token like a key. Don't paste it in chats, screenshots or files. If it leaks, regenerate it in Chromatic (Manage → Configure) and save it again with the command above.

From now on
This is your main job in review: open UI Tests, compare before/after, then accept intended changes and deny mistakes.

Glossary

WordPlain meaning
Repository (repo)The project folder plus its full history.
CommitOne saved step in the history, with a message saying what changed.
BranchA side copy where you make changes without touching the official version.
mainThe official branch. What's in main is the real design system.
Pull request (PR)A proposal to move a branch's changes into main, with review and checks.
Merge / SquashAccept a PR into main. Squash makes it one tidy commit.
CI / checkThe robot tests that run on every PR.
Branch protectionRules that stop changes reaching main without a PR and passing checks.
Organization (org)A shared GitHub space with members, teams and repos.
Team / CODEOWNERSGroups of people, and the file that says which group reviews which files.
ScopeThe first part of a package name, like @tawan-design in @tawan-design/ui.
Token (access)A password for a robot. Different from design tokens!
SecretAn access token stored encrypted in GitHub, for CI only.
BaselineThe approved image of a story that Chromatic compares new versions against.
